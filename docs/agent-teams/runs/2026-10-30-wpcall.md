## Where the design changed, and why
- `whitepages_lookup._http_get` calls `os._exit(2)` on a 401/403. In the bridge that would kill the server on a bad key. Added `AUTH_RAISES` / `WPAuthError` (12 lines, default off, CLI unchanged). `enrich_one` is otherwise used as is.
- `_run`, `_stop_run` and `_stop_why` are module globals, so the bridge serialises lookups with a lock and resets them per lookup (per-lookup `WP_MAX_SPEND`, the day cap is the ledger).
- Cost label says "about $0.22" as asked; the real worst case is $0.44 (Property miss then Person search). The card does not say $0.44; D17 and the endpoint docstring do.
- Result grading does NOT use `whitepages_lookup.lead_contacts` (it ignores the parcel `unverified` rule the bake applies). It uses `wp_contacts.parcel_owners` + `grade_property_owner` + `grade_person_record`, like the bake. `household`, `dropped` and relatives are never returned.
- Stay check is `stay_gate.check(case, sale_history_cache.json)` directly, not the bridge's `_stay_gate`, which can start a CourtListener / PACER search. A Broward / Palm Beach lead with no federal clear is therefore refused (fail closed), and so is a lead with no stay entry. Alex may want the waiver (`bk_waiver.json`) honoured here; not done.
- Cards without a number: every dial card always has a number (`r.p` is non-empty), so the only no-number card is the Find-a-number row. The button is only there.
- The shared bd_budget cap is not checked (CLAUDE.md: Whitepages has its own cap; the nightly run does not check it either).
- `wpm` is not in `send_server._merge_note`; `wpl` is local plus team sync only (board `mergeNotes` keeps local keys via `Object.assign`). Reported, not fixed.
