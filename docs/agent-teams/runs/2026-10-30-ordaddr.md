### ordaddr: ordinal suffix on numbered streets in Call Mode
- Task: "622 SE 5 AVE, Hialeah, FL 33010" must read "622 SE 5th AVE, Hialeah, FL 33010" (st / nd / rd / th, 11-13 th).
- Owner: callmode-dev
- Branch + PR: claude/agents-ordaddr @ (see commit) / docs/agent-teams/pr/ordaddr.md
- Files changed: call_mode.py (new `_ord_addr` helper + the two row sites, `a` in call_rows and coverage_rows), _addrordinaltest.py (new, git add -f), this log, the PR body.
- What changed (plain English): A bare street number after a directional (or after the house number) and before a street-type word gets its ordinal suffix. Only the text before the first comma is read, and the only edit is an inserted suffix. House numbers, routes (SR, US, HWY, STATE RD, I), units, ZIPs, already-ordinal text, and empty input are untouched. Everything that shows a row's address (card, text-template {street} and {st1}, Map link) gets the new text; `_seat_links` raw addr, parties and the JS Whitepages spelling are not touched (_wpStem passes "5th" through unchanged). Street-type list extended with MNR, MANOR, PSGE, PASSAGE found in the county data.
- Data check (board twin snapshot, field `addr`, counts only): 2,124 addresses, 1,180 change. Suffixes inserted: th 887, nd 111, rd 93, st 89. Every change verified as a pure insertion of st/nd/rd/th; second pass changes 0.
